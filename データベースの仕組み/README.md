# システムトラブルを解決せよ！（データベース講座の演習アプリ）

メルサポ特別プログラム「システムトラブルを解決せよ！～プログラミングと生成AIで探る「データベース」の仕組み～」で使う演習アプリです。
講師PCでサーバーを起動し、受講者はブラウザからアクセスします。

画面の操作を CRUD（作成・検索・更新・削除）に分類するクイズは、導入のスライド側のクイズに移り、アプリでは使いません。

| ミッション | 内容 |
| --- | --- |
| 1 | SQL で商品テーブルを直接操作する（登録・検索・更新・削除の4課題） |
| 2 | WHERE を付け忘れた UPDATE で壊れた価格を、生成AIと一緒に復旧する |
| 3 | 通販サイトの会員登録で起きるエラー（UNIQUE 制約）の原因を突き止め、お客さんが登録できるようにする（解答例は、退会した人の個人情報を消す `UPDATE 会員 SET 名前 = '退会済み', メールアドレス = '' WHERE 退会 = 1;`） |
| 4 | 会員を名前で探す画面を題材に、入力をそのまま SQL に入れる作りと、プレースホルダの作りを比べる（判定はなし。読み取り専用のデータベースで、データは変更できない） |

最初に開くのはミッション1です（練習のタブはありません）。

ミッション1〜3の画面は、左にSQLの入力欄（ターミナル）、右に通販サイトの画面を並べて表示します
（ミッション1・2は商品の画面、ミッション3は会員登録画面。SQLを実行すると、右側も自動で最新の表示になります）。
画面が狭いときは、自動で上下に並びます。ターミナルの黒い部分と通販サイトの画面は、同じ高さです。
ミッション4は、左に表示だけのターミナル（検索すると実行するSQLと、検索した結果の履歴）、右に通販サイトの検索画面と、その下にサーバー側の設定（作り方①・②の切り替え。検索するのは会員テーブルだけ）です。件数は、ターミナルの「→ N件」で見ます。
通販サイトの画面と設定の帯を合わせて、ターミナルと同じ高さにしています。

どのミッションも「🚀 開始」ボタンで始め、残り時間（分:秒）は指令書の見出しの右に表示します。
ヒント（ミッション1〜4）は、開始直後から見られます（待ち時間はありません）。
ミッション1のヒントには、CRUDの順のSQL例（クリックで入力欄に入る）があり、ミッション4のヒントには調べ方とSQLの読み方があり、ミッション2・3のヒントのプロンプト例には、見出しの行の右端に「コピー」ボタンがあります。

### SQL の入力欄（ターミナル）

ミッション1・2・3の SQL の入力欄は、sqlite3 のコマンドラインのような、黒地のターミナル風の画面です。
打った SQL と結果が、一続きに下へ積み重なります（古い入出力は残ります）。

- 最後に `;` を付けて Enter で実行 ／ Shift+Enter で改行 ／ ↑↓ で履歴 ／ Ctrl+Enter でも実行
- 「↺ 最初のデータに戻す」でデータベースを初期に戻す（履歴は残り、戻したことが1行積まれる）、「🧹 画面を消去」で履歴を消す

ミスを見つけやすくするために、次のようにしています（`lib/database_mission/sql_check.ex`）。

- 打ったコマンドの全角スペースは、色付きの枠で囲んで表示する
- `'…'` の外に全角の空白・カンマ（，、）・括弧・セミコロン・イコール・クォートがあると、SQLiteに渡さずに止めて、
  「○文字目に全角スペースがあります」のように場所を示し、コマンドの下に「^」で印を付ける（`'付箋'` のような値の中の全角文字は対象外）
- 英語のエラーはそのまま残し、その下に日本語の手がかりを出す（`near "X": syntax error`・`no such column`・列と値の数の違い）。
  UNIQUE・NOT NULL・CHECK の制約のエラーには付けない（ミッション3とその追加指令は、エラーを読むのが狙いのため）

### 追加指令（各ミッションの画面の中）

ミッション1・2・3は、必須の課題がすべて✅になると、課題欄の下に「追加指令」の区画が現れます
（ミッション2は、復旧の課題が✅になったとき）。判定はなく、そのミッションと同じデータベース（その時点の状態）で、
自分で考えて試します。SQL例は、折りたたみ（最初は閉じる）です。
一度表示されたら、「最初のデータに戻す」を押しても、表示されたままです。

### 通販サイト（ミッションの画面に埋め込み・別ページ）

ミッション1・2・3の画面は、左にSQLの入力欄（ターミナル）、右に通販サイトの画面を並べて表示します。
SQLを実行すると、右側も自動で最新の表示になります（更新の操作は不要です）。画面が狭いときは、自動で上下に並びます。

- 商品の画面（ミッション1・2）: そのミッションのデータを、通販サイトの画面として見る（見るだけ）
- 会員登録画面（ミッション3）: そのミッションのデータベースに、会員を登録する（ミッション3の課題に使う）。登録したときのサーバーのログは、会員登録画面の下に表示する

架空の店名（オフィスいちば）・メニュー・カートのアイコンなどを付けた、通販サイトらしい見た目です
（メニューは飾りで、押しても何も起きません）。

同じ内容を、別ページ（`/shop`）を別のウィンドウで開いても確認できます（講師が大きく映す用です）。
別ページでは、ミッション1・2のデータをラジオボタンで切り替えて見られます（「更新」ボタンで最新にする）。
同じブラウザ（同じ受講者）のデータベースを、セッションの識別子から引いて表示します。

## 起動

初めて使うPCでは、先に[環境構築](../環境構築/README.md)を済ませてください（Erlang・Elixir・Python 3.12の導入と、初回の`mix setup`）。

このフォルダの`start_server.bat`をダブルクリックするか、このフォルダで次を実行します。

```powershell
mix phx.server
```

既定では、サーバーを起動したPC自身（`http://localhost:4000`）からだけ開けます。
講師PCに受講者のブラウザから接続させる場合は、起動の前に環境変数を設定してください。

```powershell
$env:DATABASE_MISSION_LISTEN = "0.0.0.0"   # 全ネットワークで待ち受ける
mix phx.server
```

`http://<講師PCのIPアドレス>:4000` を受講者に案内します。
標準ユーザーで初めて全ネットワークで待ち受けると、Windowsファイアウォールの許可確認が出て、
管理者の資格情報を求められることがあります。

## 仕組み

- 受講者ごと・ミッションごとに SQLite のファイルを作り、`priv/python/run_sql.py` で SQL を実行します。
  ミッション1・2・3のファイルは、通販サイトからも見えるように、受講者ごとの決まった名前（`<識別子>_<ミッション>.db`）にします
  （ファイル名の `<ミッション>` は内部の名前のままで、m2・m3・m4 を使います）。
- 「ミッション４」タブの検索は、`priv/python/run_query.py` で、読み取り専用のデータベースに対して、1文の SELECT だけを実行します。
- ファイルは一時フォルダの `database_mission/` に置き、アプリの起動時にまとめて削除します。
- 画面を再読み込みすると、データは最初の状態に戻ります。
- 1回の実行は3秒で打ち切ります（無限に続く SQL の対策）。
- 初期データと達成判定の SQL は `lib/database_mission/missions.ex` にあります。スライドと値を合わせています。
